## The graph is the connective layer

A capability graph becomes useful when it connects the parts of a learning system that are usually handled separately. Curriculum describes what should be learned. Rubrics describe what good evidence looks like. A job-market corpus shows how capabilities appear in roles. Learning materials support practice. Assessment checks progress. Placement connects demonstrated capability to opportunity.

The graph is not a decorative map of topics. It is infrastructure for making those relationships explicit. A capability in the curriculum can point to the rubric used to evaluate it, the materials that help build it, and the job-market evidence that explains why it matters. Assessment can then refer to the same capability instead of inventing a separate vocabulary. Placement can use that shared vocabulary when matching evidence to a role.

## Shared structure, clearer questions

This connected model supports practical questions. Which learning material addresses a capability that appears often in the job-market corpus? Which rubric is used when that capability is assessed? Where does a curriculum contain a requirement without a clear path to practice? Which placement claim is supported by assessment evidence?

Those questions do not require the graph to make decisions on its own. They require it to preserve relationships well enough for people and systems to inspect them.

## A careful starting point

The first version can stay small: define the key capability relationships across curriculum, rubrics, the job-market corpus, learning materials, assessment, and placement. The value comes from a consistent connective model. More detail is useful only when it makes one of those relationships easier to understand or verify.
